# DDRGP Issue Start Prompt

別チャットへ渡せる、簡潔な日本語の開始指示文を作る。Issue・AGENTS.md・実行Skillが持つ契約を再掲せず、参照と今回固有の作業判断を残す。

## 対象と事実を確認する

- 番号だけなら現在のrepository文脈からIssueを特定し、本文・状態・URL、最新のルートAGENTS.md、対象に関係するnested規則と実行Skillの必要箇所を確認する。対象が一意でない、または取得できない場合は不足を短く確認し、本文や仕様を推測しない。
- closed/置換済みIssueを通常の新規実行対象にしない。過去Issueの開始時を再現する明示的な演習なら、その条件と現在の状態を分けて指示文を作れる。
- 引き継ぎに必要なbranch・dirty状態・直前PRのmerge等は読み取りで確認する。ユーザー申告と実測を区別し、古いbranch名・認証回避策を無条件に転記しない。
- この依頼では指示文だけを作る。対象Issueの実装、branch作成、commit、push、PR作成、外部への投稿、監視の開始は行わない。

## 参照と今回固有の指示を組み立てる

- 冒頭で対象IssueのURLと、本文を作業契約とすること、最新AGENTS.mdと該当する実行Skillへ従うことを指定する。DDRGPのIssue実行は`ddrgp-implement-github-issue`を基本の参照先とし、別workflowが対象の場合はそのworkflowを選ぶ。関連Skillを一覧から無差別に列挙しない。
- 実装、調査、仕様確定、追跡のみ等の成果物をIssueと現在のユーザー指示から判別する。仕様確定Issueではコード変更へ進めず、未確定判断は調査・根拠・推奨案を示して人間に確認するよう指定する。今ここで実行者向けの判断質問をユーザーへ投げない。
- 今回誤ると成果物が変わる注意だけを短く残す。例えば保存/復元互換性の区別、競合の再現境界、親Issueの取り込み範囲など。Scope・Acceptance criteria・Required testsの全文や実行Skillの手順は参照元に任せ、長い例示・一般的な安全事項・定型チェックリストを足さない。
- 操作範囲は現在のユーザー制限を優先し、次チャットでのIssue実行既定許可はAGENTS.mdを参照させる。指示文作成時の読み取り限定を、実行者の修正・push禁止へ転記しない。ローカルのみ・追跡のみ等の明示制限は保持する。
- 完了範囲は今回必要な差分だけ指定する。最新headのレビュー・CI確認まで依頼されているなら実行SkillのReview Follow-upへ従わせ、マージ可能通知の条件・一度だけの通知・監視終了・手動mergeを短く指定する。追跡が依頼されていないケースへ追加しない。
- 生成依頼にIssue実行の許可がないことを理由に、未来の実行依頼まで禁止しない。一方、merge・release等の別許可を創作しない。

## 出力を確認する

コピーして使える指示文を1つ返す。前置きは対象の性質や取得制限を説明するときだけ短く付ける。

出力前に、各段落が「参照先」「Issue固有の注意」「現在のユーザー指定」「確認済み引き継ぎ」のいずれかとして必要かを見直す。参照元の重複は削り、Scope拡張、未確定事項の決めつけ、未確認の完了・環境・認証情報がないことを確認する。短縮のために明示制限や重要な作業境界を落とさない。文字数や段落数は固定しない。
