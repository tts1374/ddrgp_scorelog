# DDR GP Score Tracker 画面仕様

## 1. 目的

本書は、DDR GP Score Tracker の各画面に表示する情報、画面遷移、操作、表示条件を定義する。

画面サンプル画像は、レイアウト、情報量、視覚的優先順位の参考として使用する。画像と本書が矛盾する場合は、本書を優先する。画像内の誤字、不自然な値、仕様にない要素、生成上の不整合は実装しない。

本アプリは、以下の用途を想定する。

- DDR GRAND PRIX のプレー結果を自動記録する
- 保存済みスコアを閲覧する
- 自己ベストやスコア推移を確認する
- DDR GRAND PRIX を起動せず、スコアビューアとして利用する

DDR GRAND PRIX が起動していなくても、閲覧機能は通常どおり利用できること。

### 1.1 buildごとの操作表示境界

通常画面とtask trayには、通常運用の`監視開始`と`監視停止`を表示する。

Debug buildだけ、通常の監視操作と区別した開発者向け領域を表示し、次の操作を配置する。

- `1フレーム取得`
- `連続取得を開始`
- `単発保存`

Release buildには開発者向け領域、上記操作のbutton／menu、実行可能なcommand入口を含めない。監視中または監視停止処理中は、Debug buildの開発者向け操作をUIとcommand境界の両方で拒否する。監視開始・停止の操作と、固定pathのmaster DB・正式個人スコアDB検証および既存保存境界はbuild間で変えない。

## 2. 共通レイアウト

### 2.1 ナビゲーション

左サイドバーに以下を表示する。

1. ホーム
2. 自己ベスト
3. プレー履歴
4. 設定
5. データ管理

`楽曲・譜面詳細` は独立したサイドバー項目を持たず、自己ベストの譜面一覧からのみ遷移する。

サイドバーは全画面で共通とし、現在表示中の画面を明確に示す。

### 2.2 自動記録状態

自動記録状態は、サイドバー下部にのみ表示する。ヘッダーには重複表示しない。

表示状態は以下とする。

- 自動記録：待機中
- 自動記録：準備完了
- 自動記録：解析中
- 自動記録：一時停止
- 自動記録：無効

DDR GRAND PRIX が未起動の場合も警告扱いにせず、以下のように表示する。

```text
自動記録：待機中
DDR GP 未起動
```

DDR GRAND PRIX が起動中で記録可能な場合は、以下のように表示する。

```text
自動記録：準備完了
DDR GP 検出済み
```

### 2.3 自動記録の検出動作

初回起動時に、DDR GRAND PRIX の起動や連携設定を必須としない。

自動記録が有効な場合、アプリは以下の動作を行う。

1. アプリ起動時に対象プロセスと対象ウィンドウを即時確認する
2. 未検出の場合は一定間隔で再確認する
3. 対象プロセスを検出した場合、対象ウィンドウが利用可能になるまで短時間再試行する
4. 対象ウィンドウを検出した場合、自動的にキャプチャを開始する
5. 対象プロセスまたは対象ウィンドウが終了した場合、待機状態へ戻る

初期実装では、プロセス開始イベントに依存せず、定期ポーリングによって検出する。

検出間隔は内部設定とし、通常ユーザー向けの設定項目には公開しない。

### 2.4 共通譜面表記

プレイスタイル、難易度、レベルは別属性として扱う。

- プレイスタイル：`SP` または `DP`
- 難易度：`BEGINNER`、`BASIC`、`DIFFICULT`、`EXPERT`、`CHALLENGE`
- レベル：`Lv.1` から `Lv.19`

横幅が不足する場合、難易度は以下の略称を使用する。

- BGN
- BAS
- DIF
- EXP
- CHA

Beginner と Basic を同じ `B` 表記にしない。

プレイスタイルと難易度を、`ESP` や `CSP` のような単一コードに統合しない。

### 2.5 ジャケット画像

著作権上の理由から、楽曲ジャケット画像は使用しない。

カードや一覧は、以下を中心に構成する。

- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコア
- EXスコア
- EXスコア率
- ランク

画像領域の代替として独自アートワークを必須にしない。

### 2.6 共通フィルター表示方針

フィルターは、使用頻度の高い条件を画面上部に常時表示し、使用頻度の低い条件は `詳細フィルター` に格納する。

すべてのフィルターを同時に横並び表示することは必須としない。

詳細フィルターが適用されている場合は、適用中の条件をチップとして表示する。

例：

```text
[Lv.17 ×] [AAA未達成 ×] [EX率95%未満 ×]
```

フィルター全解除操作を用意する。

## 3. ホーム

### 3.1 目的

直近のプレー状況、最新プレー、最近の自己ベスト更新を短時間で確認できる画面とする。

自動記録状態は補助情報とし、ホーム画面の主役にしない。

Phase 1では、EXスコア満点・EXスコア率はホームに表示しない。EXスコアの絶対値のみ表示する。

### 3.2 今日のプレー状況

以下を表示する。

- プレー数
- 自己ベスト更新数
- EXスコア更新数
- フルコンボ数

平均通常スコアは表示しない。

### 3.3 最新のプレー

最新の正常保存済みプレーを1件表示する。

表示項目：

- プレー時刻
- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコア
- ランク
- CLEAR状況
- FLARE
- EXスコア
- 通常スコアの自己ベスト差
- EXスコアの自己ベスト差

ジャケット画像は表示しない。

タイトル右側の星アイコンは表示しない。

自己ベスト差の表示：

- 更新：`↑ +12,340`
- 未更新：`↓ -2,180`
- タイ：`＝ ±0`
- 初プレー：`初プレー`

通常スコアとEXスコアは、別々に差分を表示する。

更新状態の配色は全画面で統一する。

- 更新：AccentPrimary
- 未更新：Danger
- タイ：TextMuted
- 初プレー：Info

同一画面内で、同じ更新状態に異なる色を使用しない。

### 3.4 判定表示

判定数・最大コンボはホームと楽曲・譜面詳細画面には表示しない。必要な詳細情報として、プレー履歴画面のプレー詳細で表示する。

### 3.5 最近のプレー

最新プレーを除く直近5件を一覧表示する。

表示項目：

- 時刻
- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコア
- EXスコア
- ランク
- CLEAR状況
- FLARE
- 通常スコア自己ベスト差
- EXスコア自己ベスト差

`すべて見る` からプレー履歴画面へ遷移する。

### 3.6 最近の自己ベスト更新

直近の自己ベスト更新を3〜5件表示する。

表示項目：

- 更新日時
- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコア更新量
- EXスコア更新量

このカードはホーム下段の横幅を使用する。

`自己ベスト更新ランキング（今日）` は表示しない。

### 3.7 データがない場合

プレーデータがない場合は以下を表示する。

- `まだプレーデータがありません`
- `DDR GRAND PRIXをプレーするか、データを読み込むとここに表示されます`

DDR GRAND PRIX の起動を必須操作として案内しない。

## 4. 自己ベスト

### 4.1 目的

SINGLEまたはDOUBLEについて、譜面単位の自己ベストを比較する。

自己ベスト画面は一覧、一覧の絞り込み、並び替え、段階表示に責務を限定する。一覧下部に自己ベストの詳細パネルは表示しない。

### 4.2 最上位切り替え

画面上部に以下を表示する。

- SINGLE
- DOUBLE

SINGLE / DOUBLE の選択は、一覧のプレイスタイルを確定する切り替えとして扱う。

選択状態は、フィルター変更、並び替え、詳細画面から戻った後も保持する。

### 4.3 プレイスタイル適用範囲

SINGLE / DOUBLE の選択は、画面内のすべてのデータと集計に適用する。

- SINGLE選択時はSP譜面のみ表示する
- DOUBLE選択時はDP譜面のみ表示する
- 異なるプレイスタイルの譜面を混在させない

以下のすべてが選択中のプレイスタイルに従うこと。

- 譜面一覧
- フィルター候補
- 対象譜面数
- 表示済み件数

### 4.4 譜面一覧

列：

- 曲名
- 譜面（難易度とレベル）
- SCORE / EX（通常スコアBESTとEXスコアBEST）
- ランク
- CLEAR
- FLARE
- プレー回数
- 最終プレー日

プレイスタイルは画面上部のSINGLE / DOUBLE切り替えで指定し、一覧の列には表示しない。

譜面列には難易度とレベルを同一列に表示する。

SCORE / EX列は通常スコアBESTを主表示し、EX SCORE BESTを同一セル内に補助表示する。

CLEARの `FULL COMBO` は `FC` と表示する。PFC、GFC、MFC、CLEARとは別の状態として表示する。

FLAREはヘッダーで意味を示し、セルには `I`〜`IX` / `EX` の値だけを表示する。FLAREの色は `chart-bests-mock.html` の定義を使用するが、色見本と凡例は表示しない。

未プレー譜面は一覧に表示し、SCORE、EX、RANK、CLEAR、FLARE、最終プレー日は `—` とする。

SINGLE選択時にDP行を表示してはならない。DOUBLE選択時にSP行を表示してはならない。

一致する譜面が50件を超える場合は、初期表示を先頭50件に制限する。譜面一覧の下端までスクロールした場合、次の50件を追加表示する。

一覧上部に、現在の表示範囲と対象件数を表示する。絞り込みまたはソート順を変更した場合は、表示範囲を先頭50件へ戻す。

### 4.5 フィルター

常時表示するフィルター：

- 難易度
- レベル
  - すべて
  - Lv.1〜Lv.19（個別に指定）
- 曲名検索

詳細フィルターに格納する条件：

- バージョン
  - 2023年配信表記はDDR GRAND PRIXとして扱う
  - DDR GRAND PRIX、DDR WORLD、DDR A3、DDR A20 PLUS、DDR A20、DDR A、DDR (2014)、DDR (2013)、X3 VS 2ndMIX、X2、X、SuperNOVA 2、SuperNOVA、EXTREME、DDRMAX2、DDRMAX、5thMIX、4thMIX、3rdMIX、2ndMIX、1stの順で表示する
- プレー状況
  - すべて
  - プレー済み
  - 未プレー
- ランク
- CLEAR状態
  - すべて
  - PFC
  - GFC
  - FC
  - CLEAR
  - 未CLEAR

詳細フィルターの適用中条件はチップで表示する。

`未更新` という曖昧な名称は使用しない。

### 4.6 ソート

一覧上部に並び順を表示し、以下を選択できる。

- スコア（高い順）
- スコア（低い順）
- 曲名（昇順）
- レベル（昇順）
- 最終プレー（新しい順）
- プレー回数（多い順）

ソート順を変更した場合は、表示範囲とスクロール位置を先頭へ戻す。

### 4.7 段階表示

対象件数に関係なく、初期表示は最大50譜面とする。

一覧下端までスクロールした場合、次の50譜面を追加表示する。対象件数に対する一律の最終上限は設けない。

### 4.8 行選択

譜面一覧の行を選択すると、楽曲・譜面詳細画面へ遷移する。

楽曲・譜面詳細画面への遷移元は自己ベスト画面のみとする。

戻った場合は、以下の状態を保持する。

- SINGLE / DOUBLE
- フィルター
- ソート順
- スクロール位置
- 表示済み件数

一覧行から楽曲・譜面詳細画面へ遷移する。詳細画面の表示内容と、戻り時の一覧状態復元は楽曲・譜面詳細画面の契約で扱う。

### 4.9 画面幅

960×640程度の表示幅でも、アプリ全体、一覧、フィルターを横方向へ切れないようにする。難易度は幅が不足する場合に `BGN`、`BAS`、`DIF`、`EXP`、`CHA` へ短縮してよい。

## 5. 楽曲・譜面詳細

### 5.1 目的

選択した1譜面について、現在の自己ベスト、成長推移、全プレー履歴を確認する。

内部的には曲単位ではなく、譜面単位で表示する。

サイドバーから直接開く画面ではなく、自己ベストの譜面一覧から遷移する詳細画面として扱う。

Phase 1では、EXスコア満点・EXスコア率・判定推移は表示しない。EXスコアは絶対値のみ表示する。

### 5.2 ヘッダー

表示項目：

- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコアBEST
- 通常スコアBEST更新日時
- EXスコアBEST
- EXスコアBEST更新日時
- RANK
- CLEAR
- FLARE
- プレー回数
- フルコンボ回数

ジャケット画像は表示しない。

タイトル右側の星アイコンは表示しない。

RANK、CLEAR、FLAREは同じ高さ、文字サイズ、内側余白の結果バッジで表示する。FLAREの色は`chart-bests-mock.html`の定義に合わせ、色見本や凡例は表示しない。

未プレー譜面では譜面情報を表示し、通常スコア、EXスコア、RANK、CLEAR、FLARE、更新日時、プレー回数、フルコンボ回数は記録なしとして表示する。

表記例：

```text
MAX 300
SP / EXPERT / Lv.17
```

### 5.3 グラフ切り替え

通常スコア推移を表示する。

プレー履歴は推移切り替えではなく、画面下部の一覧として表示する。

通常スコア推移では、以下を切り替えられる。

- 全プレー
- 自己ベスト推移

どちらも、選択中の1譜面に一致する保存済みプレーだけから構成する。`全プレー`は保存済みプレーを日時順に表示し、`自己ベスト推移`は通常スコアの自己ベスト更新点だけを表示する。EXスコア満点・EXスコア率・判定推移はPhase 1では表示しない。

### 5.4 通常スコア推移

- 横軸：プレー日時
- 縦軸：通常スコア
- 自己ベスト更新点を識別可能にする
- ランク境界線を表示できる場合は、補助線として使用する
- ホバーまたは選択時に日時、スコア、ランク、自己ベスト差を表示する

### 5.5 EXスコア率推移

Phase 1では表示しない。後続リリースで対象とする場合に、以下を表示する。

- 横軸：プレー日時
- 縦軸：EXスコア率
- 値は小数1桁を基本とする
- ホバーまたは選択時に、EXスコア、満点、率、自己ベスト差を表示する

### 5.6 判定推移

Phase 1では表示しない。後続リリースで対象とする場合に、以下を表示する。

以下を対象とする。

- MARVELOUS
- PERFECT
- GREAT
- GOOD
- O.K.
- MISS
- 最大コンボ

複数系列を同時に表示せず、1項目ずつ切り替える。

`N.G.` は表示しない。

### 5.7 最新プレー詳細

グラフ横または下部に、最新プレーを表示する。

表示項目と表示順は、ホーム画面の最新プレーと統一する。

- プレー日時
- SCORE
- EX SCORE
- RANK
- CLEAR
- FLARE
- 通常スコア自己ベスト差
- EXスコア自己ベスト差

通常スコア差とEXスコア差は、それぞれ同じ譜面の時系列上で、このプレーより前に記録された自己ベストを基準にする。初プレー、更新、未更新、タイの表示と配色はホーム画面と統一する。通常スコアBESTとEX SCORE BESTが異なるプレー由来でも、各自己ベストの値と更新日時を混在させない。

### 5.8 画面下部のプレー履歴

画面下部に、選択中の譜面に一致する保存済みプレーを日時の新しい順で1つの一覧として表示する。

表示項目：

- 日時
- SCORE
- EX SCORE
- RANK
- CLEAR
- FLARE
- 通常スコア自己ベスト差
- EXスコア自己ベスト差

自己ベスト差の基準と表示は最新プレーと同じとし、推移タブの項目を重複表示しない。未プレー譜面では一覧を表示せず、記録が存在しない空状態を表示する。

## 6. プレー履歴

### 6.1 目的

保存済みの全プレーを、日時順で検索・確認する。

### 6.2 一覧列

- 日時
- 曲名
- プレイスタイル
- 難易度
- レベル
- 通常スコア
- EXスコア
- EXスコア満点
- EXスコア率
- ランク
- 通常スコアBEST差
- EXスコアBEST差

プレイスタイルと難易度は別列にする。

### 6.3 フィルター

常時表示するフィルター：

- 期間
- プレイスタイル
- 難易度
- 曲名検索

詳細フィルターに格納する条件：

- レベル
- ランク
- EXスコア率
- 自己ベスト更新有無

自己ベスト更新有無は、以下を選択できる。

- すべて
- 通常スコア更新
- EXスコア更新
- いずれか更新
- 更新なし
- 初プレー

適用中の詳細条件はチップで表示する。

### 6.4 狭い画面での表示優先順位

横幅不足時は、以下の優先順位で列を残す。

1. 曲名
2. プレイスタイル
3. 難易度
4. レベル
5. 通常スコア
6. EXスコア率
7. ランク
8. EXスコア絶対値
9. 自己ベスト差

非表示列は、行詳細から確認できること。

### 6.5 行選択

行を選択するとプレー詳細を開く。

表示項目：

- 一覧の全項目
- 判定数
- 最大コンボ
- 保存日時
- データ取得元

OCR確信度や内部解析情報は通常表示しない。

## 7. 自動保存できない結果の通知

### 7.1 目的

自動保存できないcapture eventを、正式個人スコアDBへ保存せず、既存のWPF監視画面とtask trayへ非ブロッキング通知する。

### 7.2 表示

- 通知文：`自動保存できないプレーが発生しました。正式DBには保存されていません。`
- 確定できた発生理由とcapture event参照を補足表示する。
- 確定していない曲名、日時、スコアなどを正式値として表示しない。
- 通知中も監視と次のcapture event処理を継続する。

通知は現在の画面またはtask trayに表示し、通知履歴や専用画面は持たない。

### 7.3 非対象

- 候補選択、手動訂正、救済保存、破棄操作
- サイドバーの項目や件数バッジ
- 専用確認画面や通知履歴

## 8. 設定

設定画面はサイドバーの「設定」から開く。Phase 1では、自動記録と表示に関する4項目だけを扱う。

### 8.1 自動記録

| 項目 | 初期値 | 動作 |
| --- | --- | --- |
| アプリ起動時に監視を開始 | ON | ONの場合だけ、既存の起動時自動監視を開始する。ゲームwindowが未起動なら既存の待機状態を表示する。 |
| 保存できない結果を通知 | ON | #131で定めた `ambiguous` / `unresolved` のローカル通知だけを表示する。OFFでも診断記録、監視結果、正式DBへ保存しない境界は変えない。 |

手動の「監視を開始する」「監視を停止する」は、起動時設定に関係なく利用できる。検出間隔、キャプチャ方式、OCR、ROI、閾値は通常設定に表示しない。

### 8.2 表示

| 項目 | 選択肢 | 初期値 |
| --- | --- | --- |
| 既定のプレイスタイル | `SINGLE` / `DOUBLE` | `SINGLE` |
| 起動時に表示する画面 | ホーム / 自己ベスト / 直近プレー履歴 | ホーム |
| 言語 | 日本語 / 英語 / 韓国語 | 日本語（新しい環境ではOSの表示言語から決定） |

既定のプレイスタイルは自己ベスト画面の初期フィルターに、起動時の画面は起動後に最初に表示するサイドバー項目に適用する。言語の変更は保存後もアプリ再起動まで現在の表示を維持する。

言語は `ja` / `en` / `ko` として保存し、表示ラベルやフィルター・ソート・グラフモードの内部値には使用しない。新しい環境ではOSの表示言語が `ja*` なら日本語、`ko*` なら韓国語、それ以外は英語を初期値とする。未対応の保存言語は英語、未翻訳の表示文は日本語へフォールバックする。既存設定に言語項目がなければ日本語とし、旧形式の起動時画面ラベルも対応する内部値へ変換する。

### 8.3 保存と初期化

- 「変更を保存」を明示的に押した時点で5項目をまとめて保存する。
- 「初期値に戻す」は画面上の5項目を初期値へ戻す。保存前は実行中の監視や通知へ反映しない。
- 保存した値は次回起動時に復元する。
- 保存済み設定がない、または読み込めない場合は既定値を使用する。
- ユーザー設定は正式個人スコアDB、`plays`、保存済みプレー内容を変更しない。

## 9. データ管理

### 9.1 目的

保存済みプレーの状態、個人スコアデータのバックアップ・復元、アプリに同梱された楽曲・譜面データの状態を確認する。

### 9.2 機能

- 保存済みプレー件数、自己ベスト譜面数、最後の保存、データ状態を表示する。
- 個人スコアデータだけを対象にバックアップファイルを作成する。
- 選択したバックアップファイルを確認後に復元する。復元は現在の個人スコアデータを置き換える。
- 壊れている、または対応していないバックアップは復元せず、現在のデータを変更しない。
- 同梱された楽曲・譜面データの利用可否、データバージョン、収録譜面数を表示する。
- 同梱された楽曲・譜面データは読み取り専用で、個別の置き換え・削除を行わない。

設定、楽曲・譜面、jacket参照、source capture、解析ログ、診断ログは個人スコアデータのバックアップ・復元に含めない。復元前に確認ダイアログを表示し、キャンセル時は現在のデータを変更しない。

## 10. 空状態・エラー状態

### 10.1 空状態

技術的な原因ではなく、ユーザーの次の行動を表示する。

例：

```text
まだプレーデータがありません
DDR GRAND PRIXをプレーするか、データを読み込むとここに表示されます
```

### 10.2 自動記録待機中

警告表示にしない。

```text
自動記録は待機中です
DDR GRAND PRIXを起動すると自動で記録を開始します
```

### 10.3 読み取りできなかった場合

```text
自動保存できないプレーが発生しました
正式DBには保存されていません
```

### 10.4 データ読み込み失敗

```text
データを読み込めませんでした
ファイルを確認して、もう一度お試しください
```

内部エラー詳細は、サポート情報または開発者ログに保存する。

## 12. Codex実装時の優先順位

1. 本画面仕様を優先する
2. `design-system.md` を優先する
3. ワイヤーフレーム画像は、配置と視覚的優先順位の参考にする
4. 画像内の誤字、不自然な値、仕様にない要素を実装しない
5. 画像と仕様書が矛盾する場合は仕様書を優先する
6. 画面単位ではなく、再利用可能なコンポーネントとして実装する
7. プレイスタイル、難易度、レベルを別属性として扱う
8. SINGLE / DOUBLE の選択に異なるプレイスタイルのデータを混在させない
