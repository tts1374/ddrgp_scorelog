# DDR GP Score Tracker デザインシステム

## 1. 目的

本書は、DDR GP Score Tracker の画面全体で使用する視覚表現、コンポーネント、色、余白、状態表現を定義する。

[App 正本モック](app-mock.html)と[Web 正本モック](web-mock.html)は、[画面仕様](screen-spec.md)と本書とともに #292 で同期した。#293〜#297 は画面構成と視覚的優先順位を両モックで、配色・状態・操作の契約を両仕様書で確認する。

モック外周の `.showcase-bar`、`.concept-strip`、比較用セレクター、デモ用トースト、サンプル数値と固定の候補リストは製品仕様の対象外とする。

---

## 2. デザイン原則

### 2.1 一般ユーザー優先

開発、OCR、画像解析の知識を前提にしない。

通常画面で避ける表現：

- ROI
- OCR確信度
- キャプチャ方式
- マスタDB
- 解析失敗
- プロセス監視
- ウィンドウハンドル
- 画像ハッシュ

ユーザー向けには、結果、状態、次の行動を表示する。

### 2.2 スコアが主役

画面の視覚的優先順位は以下とする。

1. 通常スコア
2. 曲名
3. EXスコア・EXスコア率
4. プレイスタイル・難易度・レベル
5. 自己ベスト差
6. 判定数
7. 自動記録状態

自動記録状態や技術情報は補助的に扱う。

### 2.3 情報を色だけで伝えない

色に加えて、文字、符号、アイコン、ラベルを併用する。

例：

- `↑ +12,340`
- `↓ -2,180`
- `＝ ±0`
- `初プレー`

### 2.4 ジャケット画像を使用しない

楽曲ジャケット画像は使用しない。

カードは曲名、プレイスタイル、難易度、レベル、スコア情報だけで成立させる。

### 2.5 仕様上の状態を重複表示しない

同じ状態情報を、監視状態バーと画面本文の両方に重複表示しない。

自動記録状態と操作は、シェル内の監視状態欄にまとめる。

### 2.6 データ整合性を視覚表現より優先する

見栄えのために、現在の選択条件と矛盾するデータを表示してはならない。

例：

- SINGLE選択時にDP譜面を表示しない
- DOUBLE選択時にSP譜面を表示しない
- 適用中フィルターと矛盾する行を表示しない

### 2.7 UIテキストと情報の出し分け

- 通常画面は操作・判断に必要な状態と結果を中心にし、ラベルや配置から分かる説明を重ねない。仕組み・設計理由の補足は必要なものだけ詳細へ移す。
- 利用者に定着した「バックアップ」「復元」や、SP/DP・CLEAR・FLARE等のプレイヤー用語を維持する。単純な言い換えで用途や意味を曖昧にしない。
- エラー・注意は必要な場面で、失敗した操作・記録への影響・必要な対処を示す。公開範囲、送信停止と公開削除の違い、削除・復元による影響、回復時の禁止操作は省かず、判断する操作の近くに置く。診断コード・内部識別子・ファイルパスは必要時の詳細へ分け、対処に必要な情報まで隠さない。
- 「維持する」は必要な意味・結果・操作を保つことであり、説明文の常設を意味しない。まず操作名・状態・件数・個別理由へ統合し、判断に不足する内容だけを必要な場面の注意・確認・補足で示す。
- 日本語・英語・韓国語で意味と情報の優先順位をそろえ、日本語の文字数だけで採否を決めない。

現行画面を一括変更する要件にはせず、画面別Issueの範囲で適用する。個別の文言・常時表示を変える場合は、同じ変更で `screen-spec.md` と対象の既存ワイヤーフレームを同期する。

## 3. テーマ

### 3.1 対応テーマ

- Windowsに合わせる（内部値 `system`、初期値）
- 明るい（内部値 `light`）
- 暗い（内部値 `dark`）

テーマの選択肢は日本語・英語・韓国語へ翻訳する。`system`はWindowsの既定アプリモードへ追従し、OSのアプリモードを取得できない場合はライトへフォールバックする。`light`と`dark`はOS変更に追従しない。選択だけでは表示中のテーマを変えず、設定保存が成功した時点で再起動なしに反映する。`system`選択中のOS変更もアプリの実行中に反映する。

XAMLの共通styleとコードで描画するグラフ・状態表示は、ライト／ダークで同名のsemantic tokenを参照する。新しい設定や既存設定からの読み込みは、欠落・未知値を`system`へ正規化する。

Web は `public/theme.css` の `prefers-color-scheme` で OS の選択を表示中も反映する。既定値はライト。テーマのための Cookie、ブラウザーストレージ、インラインスタイルは使わず、既存の CSP を維持する。共通 CSS は公開画面と管理画面に加え、Worker が返す 404 にも適用する。

- フォーカス、選択、ホバー、押下を区別できるようにする。

- BEGINNER

- BGN

- カード：`Lv.17`

## 5. タイポグラフィ

### 5.1 推奨フォント

Windows標準環境での可読性を優先する。

- Segoe UI Variable
- Segoe UI
- Yu Gothic UI

日本語表示はOSのフォールバックを許容する。

### 5.2 サイズ

| 用途 | サイズ | ウェイト |
|---|---:|---:|
| アプリ名 | 24px | 600 |
| 画面タイトル | 30px | 600 |
| セクションタイトル | 18px | 600 |
| カードタイトル | 14px | 600 |
| 通常スコア | 28〜36px | 700 |
| EXスコア | 18〜24px | 700 |
| KPI数値 | 24〜30px | 600 |
| 本文 | 14px | 400 |
| 補助情報 | 12px | 400 |
| テーブル見出し | 12px | 600 |
| バッジ | 11〜12px | 600 |

通常スコアを主、EXスコアを第二指標として配置する。ただし、EXスコア率は明確に読める大きさを維持する。

### 5.3 数値

スコア、判定数、件数は、可能なら等幅数字を使用する。

- 通常スコア：`987,650`
- EXスコア：`2,596 / 2,690`
- EXスコア率：`96.5%`
- 自己ベスト差：符号を必ず表示
- パーセントは小数1桁を基本とする

## 6. レイアウト

### 6.1 基本グリッド

8px単位を基本とする。

推奨余白：

- ナビゲーション左右：32px
- メイン領域：左右32px、上下22px
- セクション間：24px
- カード間：16px
- カード内余白：16px
- ラベルと値：4〜8px

### 6.2 App ナビゲーション

左レールにアプリ名と主要・補助ナビゲーションを置く。背景は `BackgroundSidebar` を使う。現在の画面はアクセント、選択面、選択状態の指標で示す。幅が狭い場合はアイコンを中心にし、ラベルも確認できるようにする。監視状態欄はシェル内にまとめる。

### 6.3 ページヘッダー

各画面のページヘッダーには以下を配置できる。

- 画面タイトル
- 通知
- 画面固有の切り替えや補助操作

アプリ共通のナビゲーションと自動記録状態は配置しない。

### 6.4 メイン領域

- 最大幅を固定しすぎない
- 1200×760程度で主要画面が成立すること
- 最小サイズは960×640を目安とする
- 横幅不足時はテーブル列を段階的に省略する
- 主要操作を横スクロール前提にしない

### 6.5 App ホーム

最新結果と今日の集計を上段、最近のプレーと最近の自己ベスト更新を下段に置く。通常スコアを最も強く表示し、差分ラベルには比較時点と対象を示す。狭い画面や長い翻訳では、縦スクロールで各カードへ到達できるようにする。

## 7. コンポーネント

### 7.1 カード

用途：

- 今日のプレー状況
- 最新プレー
- 分類別サマリー
- 最近の自己ベスト更新

仕様：

- 基本パネルは1px境界線、6px角丸、通常16px／小窓12pxの内側余白とする。まとまり間は16〜24px。影は付けない
- 集計や通知など独立性が必要なカードだけ、用途に応じて全周の1px枠線を使用する
- カード内に過度な装飾を置かない
- ジャケット画像用の空き領域を作らない

### 7.2 KPIカード

構成：

- 大きな数値
- 短いラベル
- 必要な場合のみ補足

例：

```text
12
プレー数
```

平均通常スコアはKPIに使用しない。

### 7.3 難易度バッジ

- 高さ：20〜24px
- 左右余白：8px
- 角丸：4〜6px
- 文字は中央揃え
- 背景色と文字色はテーマごとに確認する

### 7.4 テーブル

- 行高：36〜44px（履歴は下記の密度を適用）
- 見出しは固定可能にする
- 行ホバー状態を持つ
- 行選択で詳細画面または詳細ペインを開く
- 数値列は右揃え
- 曲名は左揃え
- プレイスタイルと難易度は原則別列。履歴はレベルと合わせて譜面列に表示する
- 現在の分類やフィルターと矛盾する行を表示しない

履歴は一覧と選択詳細を通常サイズで左右、小窓で上下に配置する。曲名を詳細で折り返し、通常スコアを大きく、EXと日時を補足として表示する。判定の見出しは「判定」とする。

履歴の列見出しと現在の日付見出しは固定し、選択行が隠れないよう表示位置を調整する。日付はローカル表示の暦日を使う。追加読込をまたぐ同日は1つの見出しにまとめる。行高は通常約48px、小窓約40pxを目安とし、8列を保つ。件数は単位付きで示す。

### 7.5 タブ

使用箇所：

- SINGLE / DOUBLE
- レベル別 / バージョン別 / タイトル別
- 通常スコア推移 / EXスコア率推移 / 判定推移 / プレー履歴

最上位切り替えと下位タブは、視覚的階層を変える。

- SINGLE / DOUBLE：セグメントコントロール
- 分類切り替え：タブ

自己ベストは通常幅では左条件・右一覧、小窓では上部の選択欄とする。SP/DP、4つの探し方、条件の順に並べ、選択した候補を塗りと枠で示す。レベル・バージョン候補はクリックやキー選択後も常設する。右側は6指標の帯、並び順、一覧とし、通常スコアは太字、EXとレベルは12px相当、長い曲名は省略と全文tooltipを使う。目標の不足点は文末を省略せず、必要な場合は行内で折り返す。

譜面詳細は通常／EXの自己ベストと各更新日時を上段、グラフと最新プレーを中段、全履歴を下段に置く。曲名は折り返し、全体を縦スクロールする。グラフの直近100回と履歴の表示済み件数・全件数を区別する。

### 7.6 フィルター

使用コンポーネント：

- コンボボックス
- 検索ボックス
- 日付範囲選択
- 詳細フィルターボタン
- 適用中条件チップ

フィルター数が多い場合は、以下の構成とする。

- 使用頻度の高い条件：常時表示
- 使用頻度の低い条件：詳細フィルター
- 適用中条件：チップ表示

1行に詰め込みすぎず、2行表示または折りたたみを許容する。

### 7.7 フィルターチップ

例：

```text
[Lv.17 ×]
[AAA未達成 ×]
[EX率95%未満 ×]
```

- 個別解除を可能にする
- 全解除操作を用意する
- 色だけで適用状態を示さない

### 7.8 空状態

空状態では以下を表示する。

- 状況を示す短い見出し
- 次の行動を示す1文
- 必要な場合のみアクションボタン

技術的な原因説明は表示しない。

## 8. スコア表現

### 8.1 通常スコア

- 大きく表示する
- ランクを隣接表示する
- 自己ベスト差を明示する

### 8.2 EXスコア

表示形式：

```text
EX SCORE
2,596 / 2,690   96.5%
```

一覧では以下の省略を許容する。

```text
2,596 / 96.5%
```

横幅がさらに不足する場合は、EXスコア率を優先する。

プレー履歴は各プレーのEX SCORE絶対値を一覧と選択詳細に表示する。

### 8.3 更新状態

通常スコア更新とEXスコア更新を分ける。

統一ルール：

- 更新：PositiveDelta（ライト`#15803D`／ダーク`#4ADE80`）
- 未更新：Danger
- タイ：TextMuted
- 初プレー：Info

表示例：

- 更新：`↑ +12,340`
- 未更新：`↓ -2,180`
- タイ：`＝ ±0`
- 初プレー：`初プレー`

同じ状態に、画面やコンポーネントごとに異なる色を使用しない。

赤色をプラス更新に使用しない。

色だけでなく、矢印、符号、ラベルを併用する。

### 9.1 色の見方

「色の見方」は RANK、CLEAR、FLARE、フレアスキルカテゴリの順に表示する。実際のバッジ、ランプ、カテゴリ色を使い、各見本に値や範囲を文字で示す。狭い幅では見本を折り返す。App の見出しとカテゴリ名の見出しは `ja` / `en` / `ko` に対応し、DDR の正式表記は共通とする。画面側にダイアログを追加する場合は、キーボードで開閉し、閉じたら起点へフォーカスを戻せるようにする。

App は `Components.xaml` の `ColorLegendStyle` を `ContentControl` に適用する。Web は `.color-legend` とその見出し・グループ・項目スタイルに `.result-badge`、`.clear-lamp`、`.flare-category-swatch` を組み合わせる。色は現在のテーマから取得する。#292 は共通表示の提供までとし、画面への導線と配置は担当する子 Issue で定める。

| --- | --- | --- | --- |

## 10. グラフ

## 12. 文言

ホーム、自己ベスト、譜面詳細、フレアスキルと共通ナビ・状態欄は、見出しや操作から分かる説明と重複表示を省き、短い日常語を使う。共通ナビは「ホーム／自己ベスト／プレー履歴／フレアスキル／設定／記録の管理」。日付の毎朝7時切替、プレー前の自己ベストとの比較、失敗理由・対処は残す。DDRの名称、数値の意味と色、内部値・設定互換性を保ち、日本語・英語・韓国語を同期する。

「スコアの自己ベスト」「EX SCOREの自己ベスト」「スコアの変化」「全プレー」「更新したプレーだけ」を使う。差分は「プレー前の自己ベストとの差」とし、履歴にも比較時点を残す。行選択方法や曲名検索で集計しないことの常設説明は置かない。

フレアスキルは「ランク／合計／次のランクまで」を3領域へ整列し、ランク本文と付加記号を最も強く、合計を次に強く表示する。下部のCLASSIC／WHITE／GOLDは小計・版範囲・30枠中の件数を同位置へそろえ、独立スクロールの上位30譜面と固定31位の「次の候補」を並べる。通常行は約58 DIP、候補行は約60 DIPを目安とし、長い曲名は省略表示と全文ツールチップを併用する。存在しない譜面・候補行を補わない。

ランクは既存Appの`FlareRank*Brush`の方向・stopを含めて継承し、合計は`TextPrimaryBrush`、FLARE I〜EX は[色の見方](#91-色の見方)の共通トークンを使う。注意は常時表示し、計算条件を折りたたむ。異常除外0件と自明な合計・進捗説明は置かず、非0の件数・理由、読込失敗の説明は残す。960×640では次段階の不足点・閾値の折り返しと長いランク名の縮小を許可して重なりを防ぐ。

設定と記録の管理は、見出し14、通常ラベル12〜13、補足12を基本に、値と操作を先に読める強弱にする。本文のまとまりは6px角丸のCardStyleと16〜24pxのまとまり間隔で区切る。設定保存は本文外の固定欄、Webは即時操作として同じまとまりに置く。1280×760は2列、幅1100以下は縦積みで、補足の展開後も末尾までスクロールできる。画像結果は状態とファイル名の下に理由を折り返し、4区分の長い翻訳を欠落させない。

チェック項目、アカウント・詳しい情報・使える画像のExpander見出しは明暗に対応した文字色を明示する。動的な送信停止／再開の文字は表示更新後もbindingを維持する。3言語で操作の文字部分をクリックし、スクロールバー出現後も展開・保存・中断へ到達できることを確認する。HTMLは配置と余白の基準、実WPFは採用テーマ色・既存のCan*・確認・キャンセル・進捗・失敗表示を正本とする。

設定と記録の管理の本文では、Tab／Shift+Tabがコントロールの配置順に進む。設定は自動記録・表示、Web操作、固定の設定保存欄の順とし、小窓でも領域間を行き戻りしない。折りたたみ・非表示・無効の操作は、その時点の状態に従って移動対象を切り替える。

## 14. Codex実装時の優先順位

1. `screen-spec.md` を優先する
2. 本デザインシステムを優先する
3. [App 正本モック](app-mock.html)と[Web 正本モック](web-mock.html)で配置と視覚的優先順位を確認する
4. 画像内の誤字、生成上の不整合、仕様にない要素を実装しない
5. ピクセル完全一致より、再利用可能なコンポーネント構成を優先する
6. 色はハードコードせず、テーマトークンを使用する
7. プレイスタイル、難易度、レベルを別属性として扱う
8. SINGLE / DOUBLE と異なるプレイスタイルのデータを混在させない
9. 更新状態の色と符号を全画面で統一する
10. 自動記録状態を監視状態バーと画面本文へ重複表示しない

### 14.1 画面別改善の確認

既存の画面確認では、次の順で説明量・用語・操作性・重要情報の欠落を確認する。

1. 変更前後の実画面スクリーンショットを提示する。取得できない場合は未取得理由と代替プレビューを示し、実画面確認済みと扱わない。スクリーンショットはGit管理しない。
2. 人間の指摘を反映し、画面の承認を得るまで対象Issueを完了扱いにしない。一般化できた知見だけ本書へ反映する。
3. 共通改善は過去に承認された画面への遡及要否を確認する。重大な誤認・情報欠落は優先対応し、軽微な改善は親Issueへ候補として残し、必要な修正を別Issueで追跡する。
